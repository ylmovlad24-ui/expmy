# ТЗ: моушн-дизайн сайта «Внесудебная экспертиза»
Версия 1.0 — 10.11.2026
Уровень: премиальный (стандарт Awwwards 2026). Кода в ТЗ нет — только требования и параметры.

---

## 1. Цели и рамки

1.1. Задача — перевести сайт с базового уровня анимации (появление блоков, hover-тени) на премиальный: кинематографичный скролл, единая хореография страницы, один фирменный WebGL-эффект.

1.2. Приоритет: плавность и целостность важнее количества эффектов. Жюри Awwwards оценивает дизайн 40%, юзабилити 30%, креативность 20%, контент 10% — значит, ни один эффект не имеет права ломать читаемость и скорость.

1.3. Запрещено менять смыслы и тексты страниц. Разрешено менять только визуальное поведение и (по согласованию) длину слов в анимируемых заголовках для типографики.

1.4. Стек — обязательный:
- Lenis (плавный скролл) — без альтернатив по типу «свой самописный smooth scroll».
- GSAP + ScrollTrigger — вся хореография скролла.
- GSAP SplitText (или эквивалент на своём коде) — типографические эффекты.
- WebGL (Three.js или OGL) — только для одного hero-эффекта.
- Нативные CSS Scroll-Driven Animations — там, где эффект примитивен (прогресс-бар, простой параллакс), чтобы не грузить JS.

1.5. Всё должно работать при отключённом JS: контент полностью читаем, анимации — прогрессивное улучшение.

---

## 2. Глобальный слой (всё страница целиком)

### 2.1. Плавный скролл (Lenis)
- Инерция: lerp 0.09–0.11, wheel multiplier 1.0. Не «резиновый», а физически плавный.
- Обязательна интеграция с ScrollTrigger (обновление tick при событии скролла Lenis).
- При открытии модальных окон и якорных переходах — блокировка/синхронизация, без «двойного скролла».
- На тач-устройствах Lenis работает в режиме syncTouch=false (нативная прокрутка) — плавность через инерцию не имитировать artificially.

### 2.2. Прогресс чтения
- Тонкая линия прогресса страницы (2 px) сверху или сбоку — реализовать нативным CSS Scroll-Driven Animations с фолбэком на JS для Firefox/Safari.

### 2.3. Единый таймлайн секций
- Каждая секция живёт по модели entrance → hold → exit (появление, удержание, уход). Не допускается «просто fade-in» как единственный тип появления.
- Направления движения внутри страницы согласованы: если заголовки секций появляются снизу-вверх с маской, это правило действует для всех секций без исключения.

## 3. Секции страницы

### 3.1. Hero (первый экран)
- **Фон:** WebGL-эффект «жидкий градиент» (mesh/shader gradient) — 2–3 цвета: оранжевый акцент бренда + тёплый песочный + холодный серо-голубой на светлом фоне. Палитру цветов задаёт заказчик (брендовые HEX).
  - Поведение: пятна медленно перетекают (цикл 18–25 с) И реагируют на позицию курсора с лагом (интерполяция 0.03–0.06).
  - Интенсивность: прозрачность пятен 5–12%, размытие высокое; фон должен «дышать», а не «плясать».
  - Поверх шейдера — зерно (noise, статичное или очень медленное), opacity 0.25–0.35 — обязательно.
  - Производительность: 60 fps на среднем ноутбуке 2019 года; на мобильных — либо тот же эффект с пониженным разрешением (renderer scale 0.5–0.7), либо статичный CSS-градиент по брейкпоинту.
  - Пауза рендера: когда hero вне вьюпорта — WebGL-контекст останавливается (не рисуется впустую).
- **Заголовок:** кинетический вход — слова появляются по очереди, «выезжая» из-под маски снизу вверх, задержка между словами 60–90 мс, длительность каждого 600–800 мс, easing expo.out.
- **Кнопка CTA:** появляется последней, через 300 мс после заголовка.
- **Первый экран не должен блокировать первый рендер:** контент видим даже до инициализации WebGL (шейдер — поверх/подложка, текст не ждёт загрузки эффекта).

### 3.2. Карточки (направления экспертиз, «для претензии/суда/переговоров»)
- Сетка 3 колонки. Появление при входе во вьюпорт: карточки по очереди, stagger 80–100 мс, подъём на 24–30 px + fade.
- Hover: подъём 4–6 px, тень мягкая (не резкая), длительность 250–300 мс, easing power2.out.
- Зависимый hover: при наведении на карточку остальные в ряду приглушаются (opacity 0.6). Возврат — плавный, 300 мс.
- Опционально: курсор при наведении на карточку расширяется в круг с подписью «Подробнее» (см. п. 4.3).

### 3.3. «Как мы работаем» (шаги)
- Вертикальная прогресс-линия, растущая синхронно со скроллом (scrub: true, от 0 при входе секции до 100% при выходе).
- Номера шагов — гигантские полупрозрачные цифры, параллакс к содержимому (сдвигаются со скоростью 0.6–0.8 от скорости скролла).
- Каждый шаг: контент появляется снизу с маской при достижении 60–70% вьюпорта, один раз (не повторяется при обратном скролле — по согласованию; если повторный — смягчить эффект).

### 3.4. Пиннинг-секция (отличия заключения / гарантии)
- Одна секция фиксируется на экране (pin), внутри сменяются 3 тезиса по мере прокрутки.
- Смена тезиса: кроссфейд + лёгкий сдвиг по Y, длительность 500–700 мс, scrub привязан к скроллу (не по таймеру).
- Обязательный мобильный фолбэк: на экранах < 768 px пиннинг отключается, секция превращается в обычный вертикальный список (или слайдер со свайпом).

### 3.5. Горизонтальный блок (опционально, направления экспертиз)
- При вертикальном скролле содержимое едет по горизонтали (scrub). Протяжённость — не более 2–3 экранов.
- Отключить на мобильных и при prefers-reduced-motion.

### 3.6. Счётчики (цифры)
- Только реальные подтверждённые данные. Если данных нет — блок исключить из ТЗ.
- Анимация: числа накручиваются от 0 до значения при входе во вьюпорт, длительность 1.2–1.6 с, easing power2.out, разряды разделены пробелом (неразрывный).
- Повторный вход во вьюпорт — без повторной анимации.

### 3.7. Форма заявки
- Появление полей — лёгкий stagger 50 мс.
- При отправке: кнопка переходит в состояние «Отправляем…» (не прыгает по ширине), затем показывается статус-цепочка «Приняли → изучаем материалы → готовим ответ» — каждый шаг плавно появляется.
- ВАЖНО: цепочка отображает фактическое состояние. Если ответ автоматический и мгновенный — показывать реальный статус, а не фейковые этапы.
- Ошибки валидации: мягкая тряска поля (амплитуда 4–6 px, 1 цикл) + подсветка. Без красных «алертов» во весь блок.

### 3.8. Marquee-строка (опционально)
- Медленная бесконечная лента с направлениями экспертиз между секциями. Скорость — низкая, без рывков при ресайзе. Пауза при hover не обязательна.

### 3.9. Футер
- Классический приём: футер «подъезжает» из-под контента (sticky/reveal). Допустимо, если не ломает высоту страницы.

## 4. Микровзаимодействия

### 4.1. Магнитные кнопки
- CTA-кнопки притягиваются к курсору в радиусе 60–80 px, смещение до 8–10 px, пружинный возврат (elastic.out, 0.8–1 с).
- На тач-устройствах эффект отключён.

### 4.2. Кнопки
- Hover: сдвиг оттенка фона 200 мс, стрелка/иконка сдвигается на 4–6 px. Не менять размер кнопки (для избежания layout shift).

### 4.3. Кастомный курсор
- Скрыть системный курсор только на десктопе (pointer: fine). Точка 8–10 px + внешний круг с лагом.
- Состояния: над ссылками/кнопками — расширение круга; над карточками — режим «Подробнее» (круг 64–80 px с текстом).
- Если реализация курсора невозможна без деградации на тач — реализовать только точку-акцент без скрытия системного курсора.
- Доступность: системный курсор не скрывать у пользователей с prefers-reduced-motion.

---

## 5. Типографика и цвет

- Заголовки H1/H2 — анимация по словам через маску. Тексты абзацев — без посимвольной анимации (напрягает при чтении).
- Цвета анимируемых элементов — только из текущей палитры бренда. Новые цвета не вводить.
- Ключевое слово в H1 может подсвечиваться рукописным штрихом (SVG stroke-dashoffset, «прорисовка» один раз за сессию, 800–1200 мс).

## 6. Производительность и доступность (обязательные условия)

6.1. Целевой бюджет: Lighthouse Performance ≥ 85 на мобильных до и ПОСЛЕ внедрения анимаций. Если внедрение роняет балл — эффект режется, а не оптимизируется «как получится».

6.2. Анимируются только transform и opacity (плюс фильтры в WebGL). Запрещено анимировать width/height/top/left/margin.

6.3. WebGL: пауза рендера вне вьюпорта; деградация на слабых устройствах (проверка по deviceMemory/количеству ядер, порог — на усмотрение исполнителя, обосновать в комментарии кода); принудительный статичный фон при prefers-reduced-motion и при отсутствии WebGL-контекста.

6.4. prefers-reduced-motion: reduce — отключить ВСЕ скролл-анимации, WebGL-дрейф, магнитные кнопки, кастомный курсор. Контент показывается сразу, без анимаций. Это условие приёмки, а не пожелание.

6.5. Загрузка: Lenis (~3 КБ), GSAP ядра (~25 КБ gzip суммарно с ScrollTrigger), WebGL-эффект ≤ 40 КБ собственного кода. Не подключать тяжёлые библиотеки (Framer Motion,full three.js-сцены) без согласования.

6.6. CLS = 0: ни одна анимация не сдвигает layout (заголовки после SplitText должны занимать ту же площадь; шрифтовые подмены — без прыжков).

6.7. SEO и скринридеры: анимация не скрывает контент от поисковика; SplitText не должен рвать слова на строки так, чтобы ломать выделение и озвучку текста.

## 7. Что запрещено

- Глитч-эффекты, неон, кибербрутализм — не соответствуют теме экспертной конторы.
- Анимация в правовом блоке, FAQ и формах (кроме статуса отправки) — там человек читает/заполняет.
- Автопрокрутка страницы, скролл-джекинг (перехват колеса с принудительным листанием) — только естественное движение.
- Карусели-автослайдеры.
- Новые цвета, шрифты, радиальные тени-«глоу» вне палитры.
- Фейковые «этапы работы», если реальный ответ мгновенный.

---

## 8. Приёмка (чеклист)

1. Плавный скролл ощущается инерционным на десктопе; на тач — нативный без лагов.
2. Hero-шейдер: 60 fps, реагирует на курсор, останавливается вне вьюпорта, текст читается на всех кадрах анимации.
3. Заголовок собирается по словам без «прыжка» layout.
4. Карточки: stagger-появление, зависимое затемнение соседей, тень мягкая.
5. Пиннинг-секция: работает на десктопе, корректно отключается на мобильных.
6. Счётчики: реальные цифры, анимация один раз, разряды разделены корректно.
7. Форма: статус-цепочка отражает реальное состояние; ошибки валидации не «алертят».
8. prefers-reduced-motion: при включении — сайт полностью статичен и читаем.
9. Lighthouse mobile ≥ 85; CLS = 0; инпут-лаг не заметен (INP ≤ 200 мс).
10. Проверены Chrome, Firefox, Safari (macOS + iOS), Chrome Android.
11. При отключённом JS весь контент доступен.
12. Ни одна анимация не мешает выделению и копированию текста.

## 9. Порядок внедрения

Этап 1: Lenis + прогресс-линия + базовые reveal-анимации секций (проверить CLS и fps).
Этап 2: типографика (SplitText-входы), карточки, шаги с прогресс-линией.
Этап 3: пиннинг-секция, счётчики, микро-взаимодействия (магнитные кнопки, курсор).
Этап 4: WebGL hero (в последнюю очередь — он самый дорогой по времени и риску).
Этап 5: тестирование по чеклисту п. 8 на реальных устройствах, правка интенсивностей.

Каждый этап сдаётся отдельно с возможностью отката (анимации подключаются собственным файлом/модулем, не распыляются по main.css).
